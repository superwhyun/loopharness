# Review Workflow

변경 사항을 리뷰할 때는 아래 순서로 확인한다.

1. `AGENTS.md`
2. `docs/HARNESS.md`
3. `docs/ARCHITECTURE.md`
4. `docs/ADR.md`
5. 관련 diff
6. 관련 테스트

## 체크리스트

1. 아키텍처 구조를 지켰는가
2. ADR에 정의한 기술 선택을 벗어나지 않았는가
3. 새로운 기능 또는 수정에 맞는 테스트가 있는가
4. step 파일과 실제 코드 상태가 어긋나지 않는가
5. 빌드/테스트 명령이 통과하는가

## 출력 원칙

- 문제를 먼저 말한다.
- 파일/라인 또는 구체 위치를 남긴다.
- 수정 방안을 짧고 구체적으로 제시한다.
- 문제가 없으면 "no findings"를 명확히 적는다.
